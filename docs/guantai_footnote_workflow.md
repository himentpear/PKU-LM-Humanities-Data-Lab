# 观台磁州窑报告：脚注识别与正文关联

本流程在本地 RapidOCR 之后运行，不调用语言模型或外部 API。原始 OCR 行、图像、文字坐标不被改写，结构化结果独立写入 SQLite。

## 数据结构

- `footnotes`：页 ID、原始标记或 `?`、完整注释文字、原始行 ID 列表、状态、置信分数、判定证据。
- `footnote_references`：正文行 ID、原文字符起止位置、带圈标记、可为空的注释 ID、来源页修订号、原文快照和判定证据。
- `alto_blocks.block_type`：`footnote` / `footnote_candidate`；版面区域位置保持原值，页底注释不一定处于几何上的最下方 10%。
- 外键删除约束与引用位置唯一约束由数据库执行；所有关系和文档索引在同一事务写入。

## 判定步骤

1. 先保护考古编号。匹配时忽略空白，但所有偏移量仍对应原始文字。`T3③：31`、`T19③c∶328`、不完整的 `T3③`、`第③层`、`Y8火②`、`T3②、③、④层` 都不能作为脚注引用。
2. 寻找页面下部以带圈数字起始的注释。OCR 把序号和文字分成两个框时，按同行基线、左右位置和距离建立组合，仍保留两条原始行。
3. 用 OpenCV 检查注释上方的短细横线。结合小字、与正文的间隔、同页正文引用；这些是解释性证据，不是校准后的准确率。认可的页底注释区内后续注释可继承分隔线证据。
4. 序号漏识别时，检测文字左侧的小圈形图像。只保存“序号不明”候选与原图位置，绝不按顺序补号。候选边界用于避免将下一条注释吞进前一条。
5. 保留同条注释的换行，遇到下一个标记/疑似标记即停止。重复标记、缺失注释、证据弱的候选进入 `ReviewTask`。
6. 只有同页、同标记、唯一且证据充分的注释才能自动关联。`见第123页注①` 这样的跨页引用不会自动连到本页①；跨页和 OCR 未读出的标记仍需核对。注释内部的引文保留原文，不伪造进一步的引用网络。

## 校对与修订

阅读界面点击正文标记可查看已关联的脚注，再返回正文。候选与已识别结果有不同标签。

在校对任务中选择“正文引用”任务，再选择同页目标注释，填写校对人和原图依据后批准，即可确认关联。目标原为 `?` 时，由这次人工操作确认其标记；不会修改原始 OCR。拒绝注释会解除相关链接。序号仍不明的注释不能单独批准，须从正文引用确认编号。

文字获批修订后，本页旧链接标为 `stale` 并解除目标，旧字符位置不再用于界面链接。新增 `footnote_text_changed` 任务；批准此任务会按当前文字重新生成脚注候选，并把旧关系快照保存在修订记录中。每次操作均使用页修订号 CAS 防止并发覆盖。

候选脚注不进入语义提取；已识别脚注单独标注 RAG 路径 `/footnote`，不作为正文器物实体的提取来源。原始全文检索仍保留所有文字。

## 启动与审计

```powershell
.venv\Scripts\python.exe scripts/process_document.py 'docs/考古报告/3观台磁州窑址.pdf' --output data/processed/library --skip-models
.venv\Scripts\python.exe scripts/serve_library.py --library data/processed/library --port 8001
.venv\Scripts\python.exe scripts/audit_footnotes.py --manifest-id <实际文档ID>
.venv\Scripts\python.exe scripts/verify_library.py --manifest-id <实际文档ID> --output reports/guantai_library_verification.json
```

页 Bundle JSON 导出包含脚注与引用关系；ALTO 的 `Tags` / `TAGREFS` 保留块类型。审计检查整份报告的逐行原文和坐标是否与 OCR 缓存一致、页图哈希、原 PDF 哈希、关系目标和原文位置、外键、页数、Bundle 与 ALTO 导出。审计通过证明结构与来源一致，不能替代逐字准确率和人工脚注语义验收。
